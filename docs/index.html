CameraX: v1.7.0

November 18, 2026

androidx.camera:camera-*:1.7.0 is released. Version 1.7.0 contains these commits.

Important changes since 1.6.0:

1. Stabilized Camera2Interop (V2) & Kotlin DSL Builders

  • Camera2Interop V2 (Stable, No Opt-In Required): Redesigned Camera2Interop and removed the @ExperimentalCamera2Interop requirement on the new V2 APIs, providing type-safe, scope-specific configurator factory methods (Camera2Interop.forUseCase(), forImageCapture(), forSessionConfig(), and forCameraControl()) paired with setInterop() on Preview.Builder, ImageCapture.Builder, ImageAnalysis.Builder, VideoCapture.Builder, and SessionConfig.Builder, plus CameraControl.applyInteropAsync().
    • Added Kotlin DSL camera2Interop { ... } extension blocks for preview, imageCapture, imageAnalysis, videoCapture, and SessionConfig.Builder / sessionConfig, as well as CameraControl.applyCamera2Interop() (suspend) and CameraControl.applyCamera2InteropAsync().
    • Exposed granular interop scopes (UseCaseCamera2Interop, ImageCaptureCamera2Interop, SessionConfigCamera2Interop, and CameraControlCamera2Interop) providing structured access to OutputConfiguration settings (streamUseCase, mirrorMode, dynamicRangeProfile, physicalCameraId, sensorPixelModesUsed, surfaceGroupId, timestampBase), SessionConfiguration settings (sessionType, colorSpace, sessionParameter, sessionStateCallback), still capture options, and CameraCaptureSession / CameraDevice state callbacks.
    • Added helper methods and Kotlin extensions to retrieve Camera2 metadata and selectors directly: Camera2Interop.getCameraId(CameraInfo) (CameraInfo.cameraId), Camera2Interop.getCameraCharacteristics(CameraInfo) (CameraInfo.cameraCharacteristics), Camera2Interop.getCameraSelectorFromCameraId(String) (String.toCameraSelector()), and Camera2Interop.getCameraFilterFromCameraId(String).
    • Deprecated legacy Camera2Interop V1 classes (Camera2Interop.Extender, Camera2CameraControl, Camera2CameraInfo, and CaptureRequestOptions).
  • CameraX Kotlin DSL Builders: Added top-level Kotlin DSL factory functions for creating use cases and session configurations: preview { ... }, imageCapture { ... }, imageAnalysis { ... }, videoCapture(videoOutput) { ... }, sessionConfig(useCases) { ... }, highSpeedVideoSessionConfig(videoCapture) { ... }, and extensionSessionConfig(mode, extensionsManager) { ... }.

2. Compose Viewfinder Gesture, Screen Flash & Transformation Enhancements

  • Built-in Gestures, Screen Flash & Stream State in CameraXViewfinder: CameraXViewfinder in camera-compose now provides out-of-the-box support for pinch-to-zoom (isPinchToZoomEnabled, onZoomRatioChanged), tap-to-focus (isTapToFocusEnabled, onTapToFocus, autoCancelDurationMillis), screen flash (onScreenFlashReady), stream state monitoring (onStreamStateChanged with newly public Preview.STREAM_STATE_IDLE and Preview.STREAM_STATE_STREAMING), and surface release callbacks (onRelease).
  • FocusState & TransformationMode: Exposed FocusState (INACTIVE, STARTED, FOCUSED, NOT_FOCUSED, FAILED) in viewfinder-core to monitor tap-to-focus results, and added TransformationMode (DEFERRED, PRE_APPLIED) to TransformationInfo to ensure accurate viewfinder transformations in EMBEDDED mode when CameraX's OpenGL pipeline is active.

3. Video Capture & Audio Recording Enhancements

  • QHD (2K) Video Recording: Added Quality.QHD (2560×1440) and GroupableFeatures.QHD_RECORDING for 2K video capture and Feature Group queries.
  • Video & Audio Codec (MIME Type) Control: Introduced APIs for granular control over encoding formats:
    • Discover device-supported formats via experimental (@ExperimentalMimeTypeApi) Recorder.getSupportedVideoMimeTypes() and Recorder.getSupportedAudioMimeTypes().
    • Configure and inspect preferred formats via stable Recorder.Builder.setVideoMimeType(String), Recorder.Builder.setAudioMimeType(String), Recorder.getVideoMimeType(), and Recorder.getAudioMimeType().
    • Query codec-specific camera capabilities (such as supported qualities and dynamic ranges) via stable Recorder.getVideoCapabilities(CameraInfo, String).
  • Audio Channel Count & Bitrate Configuration: Added Recorder.Builder.setTargetAudioChannelCount(int) and Recorder.Builder.setTargetAudioEncodingBitRate(int) (along with Recorder.getTargetAudioChannelCount() and Recorder.getTargetAudioEncodingBitRate()) for explicit control over audio recording channels and bitrate.
  • Stabilized & Dynamic Mirror Mode: Stabilized Preview.Builder.setMirrorMode(int) (removing @ExperimentalMirrorMode) and added Preview.setMirrorMode(int), Preview.getMirrorMode(), and VideoCapture.setMirrorMode(int) to allow updating mirror mode dynamically.

4. Dynamic Concurrent Camera Composition & Visual Styling

  • Dynamic Composition Updates & Z-Order: Added ConcurrentCamera.setCompositionSettings(List<CompositionSettings>) to dynamically update Picture-in-Picture or split-screen layouts after binding to a lifecycle, and added CompositionSettings.Builder.setZOrder(int) and CompositionSettings.getZOrder() to control the rendering layer order of overlapping camera streams.
  • Frame Borders & Rounded Corners: Added setRoundedCornerRatio(float), setBorderWidthRatio(float), and setBorderColor(int) on CompositionSettings.Builder (along with getRoundedCornerRatio(), getBorderWidthRatio(), and getBorderColor() on CompositionSettings) to style concurrent camera frames with normalized rounded corners and colored borders.

5. GPU-Accelerated ImageAnalysis & Common Image Abstractions

  • PRIVATE Format & HardwareBuffer Access: Exposed ImageAnalysis.OUTPUT_IMAGE_FORMAT_PRIVATE, ImageAnalysis.getImageAnalysisCapabilities(CameraInfo).isOutputFormatSupported(int), and ImageProxy.getHardwareBuffer() as public APIs, enabling zero-copy GPU-based ImageAnalysis pipelines.
  • ImageWrapper & camera-common Abstractions: Introduced androidx.camera:camera-common and androidx.camera:camera-common-testing, providing common wrappers (ImageWrapper, ImagePlane with non-nullable ByteBuffer buffer, CameraCharacteristicsWrapper, CaptureRequestWrapper, CaptureResultWrapper) and test fakes (FakeImage, FakeCameraCharacteristics, etc.). ImageProxy and ImageProxy.PlaneProxy now implement ImageWrapper and ImagePlane.

6. Scene Detection, 3A Control, Physical Camera Binding & Auto-Rotation

  • Night Mode Indicator: Added CameraInfo.isNightModeIndicatorSupported(), CameraInfo.getNightModeIndicator(), and NightModeIndicator (UNKNOWN, NOT_RECOMMENDED, RECOMMENDED) to detect low-light scene conditions during standard capture sessions.
  • 3A Locking Mode in FocusMeteringAction: Added FocusMeteringAction.Builder.setLockingMode(int) and FocusMeteringAction.getLockingMode() to support locking AE/AWB (FLAG_AE, FLAG_AWB) or updating 3A metering regions without locking focus (FLAG_AF), allowing the camera to remain in continuous autofocus (CAF) mode while updating the focus area.
  • Physical Camera Selection & Binding: Added support for obtaining a CameraSelector for physical cameras from CameraInfo.getPhysicalCameraInfos() and binding UseCases directly to physical cameras. Querying CameraProvider.getCameraInfo() with a physical CameraSelector now returns the physical CameraInfo rather than the logical CameraInfo.
  • Automatic Sensor-Based Rotation (isAutoRotationEnabled): Added setAutoRotationEnabled(boolean) / isAutoRotationEnabled to SessionConfig.Builder, HighSpeedVideoSessionConfig.Builder, ExtensionSessionConfig.Builder, and CameraController to automatically update target output rotation from device sensors or disable the built-in rotation listener when needed.
  • Low Light Boost & Torch/Flash Interoperability: Low Light Boost and Torch now follow a "last setting wins" policy where enabling one automatically disables the other instead of rejecting the request. In addition, flash can now fire during ImageCapture while Low Light Boost is active.
  • Custom SessionConfig in CameraController: Exposed CameraController.setSessionConfig(SessionConfig, CameraSelector) to support binding custom SessionConfig instances with CameraController.
  • Extensions API Deprecation: Deprecated ExtensionsManager.getExtensionEnabledCameraSelector() in favor of ExtensionSessionConfig.

Compose Material3: v1.5.0

Nov 18 2026

androidx.compose.material3:material3-*:1.5.0 is released. Version 1.5.0 contains these commits.

Important changes since 1.4.0:

Library change announcements

  • New material3-ripple artifact and Inset Focus Rings: Added the dedicated androidx.compose.material3:material3-ripple artifact as a modern replacement for material-ripple (I1b3a3).

This library adds support for rendering focus states using visual inset focus rings instead of opacity layers. Within material3, this integrates seamlessly via LocalRippleThemeConfiguration (I0551a). Standalone design systems can also depend directly on androidx.compose.material3:material3-ripple.

Behavior Changes

  • Slider and RangeSlider stateful migration & source-breaking parameter change:

    • Stateless overloads of Slider and RangeSlider are deprecated in favor of stateful overloads taking SliderState and RangeSliderState (If8995).
    • Source breaking change: onValueChange is now a required parameter, and its position in the parameter list has changed. Slider and RangeSlider now handle onValueChange and onValueChangeFinished directly in the composable layer rather than passing them through SliderState (I959ac).
    • In RangeSliderState, activeRangeStart and activeRangeEnd have been renamed to startValue and endValue (If8995).

    Migration Example:

    // Before (Stateless)
var value by remember { mutableFloatStateOf(0.5f) }
Slider(value = value, onValueChange = { value = it })

// After (Stateful)
val state = remember { SliderState(value = 0.5f) }
Slider(state = state, onValueChange = { /* optional side effects */ })

  • SecureTextField Default Obfuscation Mode: Updated SecureTextField and OutlinedSecureTextField to default to TextObfuscationMode.System rather than TextObfuscationMode.RevealLastTyped (I76c7e).

  • BottomSheet Deterministic Anchor Resolution: ModalBottomSheet and BottomSheetScaffold no longer automatically remove the PartiallyExpanded anchor based on layout height heuristics (Ia4167. Developers explicitly control anchors via rememberBottomSheetState. Sheets also now respect MaterialTheme.motionScheme during nested scrolling and dragging (I5fe22).

  • Navigation Item High-Contrast Label Color: Horizontal NavigationItem labels (e.g. in WideNavigationRail) now calculate color via selectedTextColorStartIconPosition to match selectedIconColor under high-contrast themes (I85855, b/490910896). To revert, set selectedTextColorStartIconPosition = MaterialTheme.colorScheme.secondary.

  • Checkbox Sizing & Alignment: Checkbox box size and indicator marks have been recalibrated to strictly align with the Material 3 specification (I97baf, b/457504316). Flag ComposeMaterial3Flags.isCheckboxStylingFixEnabled is provided to assist testing and rollout.

  • TopAppBarDefaults Scroll Behaviors: pinnedScrollBehavior and enterAlwaysScrollBehavior overloads now take ScrollableState (LazyListState, ScrollState) to resolve reversed layout directions and initially scrolled offsets (Idef9d, I9d5c2). Parameter isAtTop is renamed to isAtStart (If7323).

  • Single Theme Composition Local: MaterialTheme was refactored internally to consolidate theme values into a single composition local (MaterialTheme.LocalMaterialTheme.current) (Idee2e). Deprecated LocalMotionScheme in favor of MaterialTheme.motionScheme (I4b61d).

New Material Design 3 Components

  • Expressive Buttons & Button Groups:
    • ToggleButton, ElevatedToggleButton, FilledTonalToggleButton, and OutlinedToggleButton: Toggle buttons featuring expressive shape morphing, ButtonSize, and icon slots (Iab484).
    • SplitButton: Expressive split button combining a primary action button and a trailing menu/dropdown trigger, replacing SplitButtonLayout (Ic9840).
    • ButtonGroup: Container for grouped buttons supporting adaptive width squishing via Modifier.animateWidth(compressionLimit = ...) and overflow indicators (I8ef39, I6e67c).
  • Expressive Text Fields:
    • TextField and OutlinedTextField expressive styling options featuring TextFieldDefaults.roundedShape, tonalColors(), and TextFieldLabelPosition.Inside / Cutout label placement (Id9185, I40f62).
  • Expressive Chips:
    • FilterChip, ElevatedFilterChip, and InputChip with shape-morphing selection animations, custom content padding, and horizontalArrangement support (I84717, Ida874).
  • Expressive Menus & Submenus:
    • SelectableDropdownMenuItem and CheckableDropdownMenuItem: Expressive menu items supporting radio and checkbox selection semantics, supporting text, and vibrant colors (I160ca, I89e4b).
    • DropdownMenuPopupPositionProvider: Enables anchor-relative popup positioning for nested cascading submenus (Ic1ace).
  • Expressive Time Pickers & Pickers:
    • VibrantTimePickerDialog: Expressive time picker dialog supporting both dial and uncontained scroll/input modes (Iea5aa, I2b3b6).
    • Scrollable TimePicker variant and ScrollField: Wheel/scroll picker variant for rapid numeric selection with full keyboard and screen reader accessibility (I46f6b, Iab612).
  • Sheets and Scrims:
    • Standalone static Sheet component (Experimental): Non-modal static surface for anchored bottom and side sheets (I0ef95).
    • Standalone Scrim: Decoupled scrim composable for use across modal sheets, dialogs, and custom containers (I29555).
  • Wavy Progress Indicators:

Compose Runtime: v1.13.0

November 18, 2026

androidx.compose.runtime:runtime-*:1.13.0 is released. Version 1.13.0 contains these commits.

Important changes since 1.12.0:

ComputedState API

We've introduced a new computedStateOf { } API that can be used as an alternative to derivedStateOf.

Like DerivedState, ComputedState is an implementation of State whose value is backed by a calculation that may read other states. The value will invalidate when the result of the calculation changes, not when one of the referenced states changes.

The primary difference between ComputedState and DerivedState is that DerivedState caches the result of its calculation and ComputedState executes the calculation on-demand each time the value is read. For many calculations, this caching is more expensive than computing the value on-demand. Therefore, we recommend using ComputedState instead of DerivedState when your calculation doesn't benefit from caching. Good candidates for calculations that don't benefit from caching are ones that don't rely on object identity of its result, don't allocate large objects, don't read many states, aren't read many times in a single frame, and don't perform a complex algorithm.

As a general rule of thumb, we recommend using ComputedState instead of DerivedState for most usages and if it's unclear whether caching would be beneficial.

Updates to the Experimental SlotTable

The LinkComposer remains opt-in as of Compose 1.13, and includes fixes for several issues reported since Compose 1.12. We continue to recommend testing your app against the new implementation of the SlotTable and reporting any issues you run into.

Note that in runtime version 1.13.0-alpha01, the proguard syntax for enabling the LinkComposer in minified builds has changed. See the feature flag documentation and previous release notes for more information.
